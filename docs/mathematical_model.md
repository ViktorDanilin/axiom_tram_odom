# Математическая модель движения трамвая

## Структура модели

Динамический узел реализует последовательность:
```{math}
n \rightarrow T_{\rm req} \rightarrow T \rightarrow \omega \rightarrow
\Delta \rightarrow F_{\rm adh} \rightarrow a \rightarrow v \rightarrow s.
```

Состояние физической модели:
```{math}
\mathbf{x}_{\rm phys}=\begin{bmatrix}v&s&\omega&T\end{bmatrix}^{\mathsf T},
```
где $v$ — скорость кузова, $s$ — путь, $\omega$ — угловая скорость эквивалентного ведущего колеса, $T$ — фильтрованный суммарный момент на колёсах.

Основные входы: ступень контроллера $n$, масса $m$, уклон $\alpha$, категория сцепления `adh_cond`, измерения скоростей передней и задней тележек. Все внутренние величины приводятся к СИ.

## Нелинейная модель тягового привода

Запрашиваемый суммарный момент на колёсах задаётся кусочно-линейной зависимостью от ступени контроллера:
```{math}
T_{\rm req}=\begin{cases}
 k_+n, & n>0,\\
 k_-n, & n\leq0,
\end{cases}
\qquad
T_{\rm req}\leftarrow\max(T_{\rm req},-T_{\rm brake,max}).
```

При $\omega_+=\max(\omega,0)>10^{-3}$ рад/с запрошенный момент дополнительно ограничивается мощностью. Для положительной тяги:
```{math}
T_{\rm req}\,\omega_+ \ge P_{\max}
\quad\Rightarrow\quad
T_{\rm req}=\frac{P_{\max}}{\omega_+}.
```
Для торможения:
```{math}
T_{\rm req}\,\omega_+ \le -P_{\rm brake,max}
\quad\Rightarrow\quad
T_{\rm req}=-\frac{P_{\rm brake,max}}{\omega_+}.
```

Динамика привода аппроксимирована апериодическим звеном первого порядка:
```{math}
\dot T=\frac{T_{\rm req}-T}{\tau_T}
=2\left(T_{\rm req}-T\right),
\qquad \tau_T=0{,}5\ \text{с}.
```

В текущей конфигурации:
```{math}
k_+=937\ \text{Нм/ступень},\quad
k_-=1422\ \text{Нм/ступень},\quad
T_{\rm brake,max}=7100\ \text{Нм},\quad
P_{\max}=288000\ \text{Вт},\quad
P_{\rm brake,max}=I_{\rm brake}^2R_{\rm brake}
=320^2\cdot2{,}2=225280\ \text{Вт}.
```
Это суммарные моменты на колёсах, поэтому передаточное число повторно не применяется. Коэффициенты откалиброваны по записи `30618_88aea4d9_gt`; они не заявляются как паспортная характеристика тягового двигателя. Постоянная времени берётся из `observer.drive_tau_s` в `json/tram.json`.

## Колесо, сцепление и проскальзывание

Линейная разность между окружной скоростью колеса и скоростью кузова:
```{math}
\Delta=R\omega_+-v_+,
\qquad
v_+=\max(v,0),\qquad
\omega_+=\max(\omega,0).
```

Сила сцепления одного ведущего колеса:
```{math}
F_{\rm adh,1}=\frac{mg}{N}
\left(c e^{-a\Delta}-d e^{-b\Delta}\right),
```
а суммарная сила сцепления:
```{math}
F_{\rm adh}=N_dF_{\rm adh,1}k_{\rm adh}.
```
Здесь $k_{\rm adh}$ — вход модели `adh_scale`. В ROS-узле он адаптируется по колёсной скорости: начальное значение 1, диапазон 0,5–1,2.

Принято $N=8$, $N_d=8$, $g=9{,}80665$ м/с$^2$. Наборы $(a,b,c,d)$ зависят от `adh_cond`:

| `adh_cond` | $a$ | $b$ | $c$ | $d$ |
|:----------:|:-----:|:-----:|:-----:|:-----:|
|     0      | 0.54  |  1.2  |  1.0  |  1.0  |
|     1      | 0.54  |  1.2  |  0.2  |  0.2  |
|     2      | 0.54  |  1.2  |  0.1  |  0.1  |
|   прочие   | 0.05  |  0.5  | 0.08  | 0.08  |

Суммарная инерция эквивалентных ведущих колёс:
```{math}
J=N_d\frac{1}{2}m_wR^2,\qquad m_w=195\ \text{кг}.
```

Уравнение вращения:
```{math}
J\dot\omega=T-RF_{\rm adh}.
```

При $|R\omega-v|>\delta_{\rm slip}$ ROS-узел выполняет численную пересинхронизацию
```{math}
\omega\leftarrow\frac{v}{R},
```
где `slip_resync_limit_mps` задаёт $\delta_{\rm slip}$ (по умолчанию 5 м/с). Это защитная численная эвристика от расходимости экспоненциальной модели, а не полноценная физическая антипробуксовочная система.

## Сопротивление движению

Для $v_+>0$:
```{math}
F_{\rm res}=0.0147m+125.83v_+ + mg\sin\alpha.
```
При $v_+=0$ сопротивление в реализации полагается равным нулю.

## Ускорение, скорость и путь

Продольное ускорение вычисляется непосредственно из баланса сил:
```{math}
a=\dot v=\frac{F_{\rm adh}-F_{\rm res}}{m}.
```

Путь:
```{math}
\dot s=v_+.
```

Таким образом, ускорение не получается разностным дифференцированием шумной скорости колеса. Это принципиально снижает чувствительность к высокочастотному шуму одометрии.

Непрерывная модель интегрируется трёхстадийным RK3 (`ode3`). ROS-адаптер делит интервал между входными сообщениями на
```{math}
N_h=\left\lceil\frac{\Delta t}{h}\right\rceil
```
подшагов, где максимальный шаг $h=0{,}001$ с жёстко задан в ROS-узле. Параметра ROS `model_dt_s` в текущей реализации нет.

## Коррекция по колёсной одометрии

Детектор проскальзывания проверяет очередное измерение скорости тележки. Если обе тележки исправны и их показания согласуются, $v_w$ равно среднему двух скоростей; иначе используется принятое показание одной тележки. При отклонённом измерении коррекция не выполняется. Для принятого измерения модель корректируется с эффективным коэффициентом $g_c=g_0q$, где $g_0$ — `wheel_correction_gain`, а $q$ — доверие детектора к измерению:
```{math}
v\leftarrow\max\left\{v+g_c(v_w-v),0\right\},
```
```{math}
\omega\leftarrow\max\left\{\omega+g_c\left(\frac{v_w}{R}-\omega\right),0\right\}.
```

По умолчанию $g_0=0{,}5$; $q=1$ для доверенного измерения и уменьшается при восстановлении датчика. Второе показание допускается к усреднению в течение 0,6 с после его получения. `wheel_max_age_s=0,25` с задаёт порог свежести для диагностики, а не фильтр этой коррекции. При разрыве временных меток более 3 с интегрирование большого интервала пропускается.

## Оценка положения

В динамическом режиме EKF хранит состояние
```{math}
\mathbf{x}_{\rm EKF}=\begin{bmatrix}x&y&\psi&\kappa&v&a\end{bmatrix}^{\mathsf T},
```
где $(x,y)$ — координаты, $\psi$ — курс, $\kappa$ — кривизна траектории, $v$ — скорость, $a$ — ускорение.

Прогноз положения выполняется по скорости, курс изменяется пропорционально $v\kappa$. В измерительный апдейт поступают принятая детектором колёсная скорость и ускорение физической модели. GNSS учитывается при включённом `gnss_fusion` (по умолчанию включён): до привязки к маршруту корректирует положение EKF, после привязки может корректировать его скорость по продвижению вдоль маршрута.

При `position_source=route` положение продвигается вдоль маршрутной геометрии по приращению
```{math}
\Delta s_{\rm route}=v_{\rm model}\,\Delta t\,k_s,
```
где $k_s=$ `route_distance_scale`. При `position_source=ekf` до привязки используется положение EKF. После привязки отдельный маршрутный указатель продвигается на $v_{\rm EKF}\Delta t\,k_s$, при наличии свежей GNSS-оценки продольной координаты это приращение может корректироваться; затем поза EKF согласуется с маршрутом.

## Входы и выходы математической модели

**Входы:** команда контроллера, скорости передней/задней тележек, параметры трамвая и сцепления, временная метка, опционально начальная GNSS-привязка и маршрут.

**Выходы физической модели:** продольная скорость $\hat v$, ускорение $\hat a$, накопленный путь $\hat s$ и диагностические величины. **Публикации ROS-узла:** скорость (из EKF или физической модели согласно `velocity_source`), оценка позиции/курса и диагностические состояния. Накопленный путь физической модели хранится во внутреннем состоянии и отдельно в ROS не публикуется.
